# Лабораторная работа №3 — Виртуальная память

## Цель работы

На практике изучить особенности выделения памяти операционной системой и влияние страниц памяти, TLB и кэш-памяти процессора на производительность программ.

## Эксперимент №1. «Выделить — не значит получить»

### Описание

Эксперимент демонстрирует разницу между выделением виртуального адресного пространства и фактическим использованием физической памяти.

Программа выполняет следующие действия:

1. Измеряет начальные значения VmSize, RSS и количества minor page faults.
2. Создаёт временный разреженный файл размером 256 МиБ.
3. Отображает файл в память с помощью MappedByteBuffer и FileChannel.MapMode.PRIVATE.
4. Измеряет показатели после отображения.
5. Выполняет первое чтение по одному байту из каждой страницы и рассчитывает контрольную сумму.
6. Записывает значение 1 в первый байт каждой страницы.
7. Повторяет запись в те же позиции, используя значение 2.
8. Проверяет четыре записанные позиции.
9. Освобождает отображение памяти, измеряет показатели повторно и удаляет временный файл big.bin.

Для измерения VmSize и RSS используется `/proc/self/status`, для подсчёта minor page faults — `/proc/self/stat`. Время выполнения операций измеряется с помощью `System.nanoTime()`.

**Примечание:** используется файловое PRIVATE-отображение временного разреженного файла, а не анонимный mmap.

### Результаты

Размер выделяемого блока — 256 МиБ.

Количество страниц:

```text
268 435 456 / 4096 = 65 536 страниц
```

Результаты измерений:

| Этап | VmSize, МиБ | RSS, МиБ | Прирост minor faults | Время, мс |
|---|---:|---:|---:|---:|
| Начало | 3254,54 | 44,36 | 0 | — |
| После выделения | 3510,54 | 47,01 | 557 | — |
| После первого чтения | 3510,54 | 303,25 | 574 | 202,468 |
| После первой записи | 3510,54 | 303,38 | 65 578 | 312,148 |
| После повторной записи | 3510,54 | 303,49 | 28 | 3,296 |
| После освобождения | 3254,54 | 48,89 | 446 | — |

Контрольная сумма первого чтения составила 0, поскольку временный разреженный файл предварительно не заполнялся данными.

Все четыре проверенные позиции после повторной записи содержат значение 2.

Первая запись оказалась приблизительно в **94,7 раза медленнее** повторной записи.

### Вывод

Отображение файла в виртуальное адресное пространство не означает немедленного использования всего соответствующего объёма физической памяти. Эксперимент показал изменение VmSize и RSS при выделении, первом чтении и записи страниц.

При первой записи наблюдался значительный прирост minor page faults, связанный с обработкой обращений к страницам и механизмом Copy-on-Write. Повторная запись выполнялась значительно быстрее, поскольку страницы уже были подготовлены для записи.

После освобождения отображения VmSize вернулся к исходному значению, а RSS приблизился к начальному показателю.

## Эксперимент №2. «Матрица по строкам и по столбцам»

### Описание

Эксперимент показывает, как порядок обращения к элементам массива влияет на производительность программы.

Создаётся одномерный массив `int[]` размером:

```text
N = 8192
8192 × 8192 = 67 108 864 элементов
```

Общий объём элементов массива составляет 256 МиБ.

Реализованы два способа обхода:

- **По строкам** — последовательное чтение соседних элементов массива.
- **По столбцам** — чтение элементов с шагом `N` элементов.

Перед измерениями выполняется прогрев обоих методов. Каждый способ измеряется три раза, после чего рассчитывается среднее время выполнения.

### Результаты

| Измерение | По строкам, мс | По столбцам, мс |
|---|---:|---:|
| 1 | 12,25 | 5628,88 |
| 2 | 20,25 | 5557,07 |
| 3 | 19,59 | 5642,87 |
| **Среднее** | **17,37** | **5609,61** |

Дополнительные результаты:

| Показатель | Значение |
|---|---:|
| Сумма по строкам | 3 321 887 616 |
| Сумма по столбцам | 3 321 887 616 |
| Контрольная сумма | 19 931 325 696 |
| Отношение среднего времени | ≈ 322,9 раза |

### Вывод

Обход массива по строкам оказался приблизительно в **322,9 раза быстрее** обхода по столбцам.

Это объясняется последовательным расположением элементов в памяти, эффективным использованием кэш-линий и особенностями работы TLB. При обходе по столбцам расстояние между соседними обращениями составляет 32 768 байт, что ухудшает пространственную локальность доступа к памяти.

## Запуск программ

Для выполнения экспериментов необходимы Linux или WSL2 и установленный JDK.

### 1. Запуск первого эксперимента

```bash
javac MemoryExperiment.java
java -Xmx512m MemoryExperiment
```

Программа создаст временный файл `big.bin`, выполнит измерения и удалит его после завершения эксперимента.

### 2. Запуск второго эксперимента

```bash
javac MatrixExperiment.java
java -Xmx1g MatrixExperiment
```

Программа выведет суммы элементов, контрольную сумму, результаты трёх измерений и среднее время обхода массива.
